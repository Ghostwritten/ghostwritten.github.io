About Me

April 15, 2025 · 7 min read
ghostwritten
ghostwritten maintainer

👋 你好​

欢迎来到我的技术世界！我是Ghostwritten，一名痴迷于云原生技术栈的DevOps工程师和技术博主。如果你正在阅读这段文字，那么我们大概已经在这个由代码和创意构成的宇宙中相遇了。

作为一个终身学习者，我将这个博客（https://ghostwritten.github.io/）视为我技术航行的日志本，记录着我在技术海洋中发现的每一处值得分享的风景。

👨‍💻 我的背景​

我的技术旅程始于对计算机基础的好奇，尽管我的大学专业是中药学，但在毕业之后直接从事了计算机领域方面的工作，主要从事于云计算、容器技术和自动化运维等领域。多年来，我逐渐形成了自己的技术栈：

  • 容器与编排：Docker、Kubernetes成为我日常工作的核心工具，我热衷于探索它们的最佳实践和实现细节
  • 云原生生态：从Prometheus到Istio，从Helm到ArgoCD，这些工具构成了我的技术调色板
  • 基础设施即代码：Terraform、Ansible等工具帮助我将基础设施管理变为可重复、可版本控制的过程
  • 脚本与编程语言：Shell、Python、Go是我最常用的语言，我相信掌握适合的工具对解决问题至关重要

在这些领域的探索过程中，我深刻体会到了开源社区的力量。这也是我创建博客的初衷之一：回馈社区，分享知识。

✍️ 为什么写博客？​

更深的理解，来自写作​

为什么写博客？对我而言，这不仅是一种分享，更是一种学习方法。正如费曼所说："如果你不能简单地解释它，你可能并没有真正理解它。"当你能把一个知识点讲明白，或者用自己的语言重新解释，它才真正属于你。

很多人看了很多视频、教程，觉得“我懂了”。可当他需要写一段代码，或者向别人解释，却发现什么都说不清楚。这种“错觉的掌握”只有写作能打破。

所以，我写博客，不是为了告诉别人我懂什么，而是为了问自己一句：

你真的懂了吗？

留给未来的自己​

过去的我，习惯把笔记写在各种地方：本地 Markdown 文件、印象笔记、OneNote、Typora……

可几年后回头一看，零散又难以检索。

现在，我把这片博客当作我的技术“备忘录”和“成长日志”。或许某天，我遇到了曾经解决过的问题，回头看看这篇博客，能对自己说：

啊哈，那时我还写过这个呢！

给他人一点参考​

互联网让我学到了无数好文章、好经验。能从一个陌生网友的技术博客中找到灵感，解决问题，是一件非常温暖的事。

如果将来，我写的某篇文章，也刚好能帮到某位在深夜调 bug 的开发者，那就很值得。

💡 我会在这里写些什么？​

这个博客不追求华丽，不追热点，它更像是一份技术人的“成长实录”。

目前我计划写的内容包括：

  • 运维日常的经验总结（K8s、Podman、Harbor、OpenShift 等）
  • 个人效率工具分享（终端美化、快捷脚本、开发环境搭建）
  • 思考类内容（比如：运维的未来、前端的演变、全栈到底是不是幻觉？）

有时候也会写些非技术内容，比如读书记录、生活观察、工作感悟。因为我始终相信：

技术是生活的一部分，而不是生活的全部。

📢 与我联系​

技术是一场持续的对话，而非独白。我非常珍视与读者的互动和交流。如果你有任何问题、建议或者想法，欢迎通过以下方式与我联系：

  • GitHub：查看我的项目和代码实践
  • Email（1zoxun1@gmail.com）：技术讨论、内容建议，或者只是想聊聊天
  • 评论区：在博客文章下方留言，分享你的想法和经验

每一次交流都是一次学习的机会，也是技术社区建设的一部分。

🔚 最后的一点点仪式感​

GhostWritten，是我的博客名。

它源自英国作家 David Mitchell（大卫·米切尔） 的小说《Ghostwritten》（中译：《幽灵代笔》）。这是一部结构极为巧妙、风格多变的小说，它以九个看似毫无关联的故事串联起全球九个角落，描绘出一个有关 命运、联系、传递 与 身份认同 的宏大叙事。

每一章的主角都像是一位“代笔人”—— 他们讲述着自己的故事，但这些故事之间，却又隐藏着丝丝缕缕的因果关联。

我喜欢这种感觉：

  • 你说出了一个看似个人的片段，却唤起了别人内心的共鸣。

  • 你留下了一段代码，未来的你或者某个陌生人却因此受益。

  • 你写下了一篇笔记，在数月后成了自己排忧解难的指南。

GhostWritten，不只是代笔。 它是穿越时间和空间的连接。

谢谢你读到这里 🙏

Write code like poetry. Write blogs like letters.
—— GhostWritten
